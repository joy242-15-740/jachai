# Jachai — Rules Compliance Checklist

Sources: AI Hackathon Rulebook (HR), General Rules (GR), Student Project
Guideline (SG). If an official announcement differs from a general rule, the
competition-specific instruction wins (GR 11.2). When unsure, ask through the
official clarification channel and keep the written answer (GR 10.1).

## Team and accounts

- [ ] Max 3 members, all officially registered; no substitutes (HR 2.1, 2.2).
- [ ] Every member uses their **own** AI accounts (Claude, LLM API); no
      sharing (GR 5.3, 4.3).
- [ ] Every member commits under their own Git name and email.
- [ ] Every member can explain the design, the data, the models and the AI
      parts (HR 4.5, 9.4). Rehearse questions on each other.

## Development period

- [ ] No Jachai code written before T+0. Planning documents are fine; the
      solution is built during the period (HR 4.1, 4.3, 9.3).
- [ ] Repo is public on GitHub (HR 5.1).
- [ ] Small commits, pushed several times a day, by every member (HR 5.2, 5.3).
- [ ] Initial code pushed **before** the initial deadline (HR 5.5).

## Originality and sharing

- [ ] Nothing copied from other teams' repos: no code, text, prompts, design
      (HR 9.1, GR 4.4).
- [ ] Nothing shared with other teams: no code, prompts, data, files,
      credentials, contest info (GR 4.2).
- [ ] No external human help during the active competition: no seniors,
      mentors or friends writing or fixing code (GR 4.1). Agent or shop
      interviews only if the organisers confirm in writing that it is allowed.
- [ ] Every external library, model, API and dataset listed with licence in
      `docs/third_party.md` (HR 4.4, 9.2).

## AI tools

- [ ] AI tools are allowed without limit (GR 5.1); we are responsible for
      everything they produce (GR 5.4). Review and test all generated code.
- [ ] Keep Claude Code sessions and `docs/ai_usage.md` so we can show prompt
      and development history if judges ask (GR 5.6, 7.4).
- [ ] Never use AI to obtain leaked material, access restricted information
      or bypass rules (GR 5.5).

## Data and responsible AI

- [ ] Synthetic or public data only; no real personal data (SG 11, 14).
- [ ] No automatic blocking; a human approves every action (SG 14).
- [ ] Explainability, fairness check, security, transparency shown in the
      product and the report (SG 14).
- [ ] Honest claims: no "100% detection", synthetic results labelled as such.

## Submission (by T+72 hours)

- [ ] Public GitHub repo link (HR 7.1).
- [ ] README with all 10 sections, exact commands and a working live URL;
      secrets as placeholders (HR 6).
- [ ] Video: how it works, features, AI components, real-life impact (HR 7.2).
- [ ] Report: problem, idea, solution, key features, AI approach, impact
      (HR 7.3).
- [ ] Format and channel exactly as the organisers specify; submit early and
      check the links open in a private window (GR 6.1, 8.1). Late
      submissions are not accepted (GR 6.2).

## Final day (7 October)

- [ ] Valid institutional ID card for every member (GR 1.2).
- [ ] Own laptops, chargers, and a backup internet connection (HR 2.3, GR 2.2).
- [ ] Arrive on time; late entry allowed up to 1 hour but no extra time
      (GR 3.2).
- [ ] New requirements implemented within the allotted time, committed step
      by step and pushed before the window closes (HR 5.5, 8.3).
- [ ] Final 90 minutes: demo the updated project, explain the new changes,
      answer judges' questions (HR 8.4).
- [ ] Report any technical problem to organisers immediately (GR 7.5, 10.3).

## Conduct

- [ ] Follow organisers', invigilators' and judges' instructions (GR 7.1).
- [ ] Never interfere with the contest network, platform, devices or other
      teams (GR 7.2, 7.3).
- [ ] Be ready to show screen, prompt history, code and repository for
      integrity checks (GR 7.4).
